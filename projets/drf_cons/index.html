    Consommer l'API avec un script Python

    Pour cette étape, nous allons sortir de l'univers Django. Nous allons créer un petit script indépendant qui va "parler" à notre API pour récupérer les articles.

    1. Installation de la bibliothèque requests

    C'est l'outil standard pour envoyer des requêtes HTTP en Python.

    #Windows
pip install requests
#Mac
pip3 install requests

    2. Le script client (client.py)

    Créer ce fichier n'importe où sur votre ordinateur (en dehors du dossier Django) :

    import requests

# L'URL de votre API locale
URL = "http://127.0.0.1:8000/api/posts/"

def recuperer_articles():
    try:
        # Envoi d'une requête GET
        response = requests.get(URL)

        # Vérification si la requête a réussi (Code 200)
        if response.status_code == 200:
            articles = response.json() # On transforme le JSON en liste Python

            print(f"--- Liste des {len(articles)} articles du Blog ---")
            for post in articles:
                print(f"Titre : {post['titre']}")
                print(f"Auteur : {post['auteur']}")
                print("-" * 30)
        else:
            print(f"Erreur : {response.status_code}")

    except requests.exceptions.ConnectionError:
        print("Erreur : Le serveur Django n'est pas lancé !")

if __name__ == "__main__":
    recuperer_articles()

    3. Pourquoi est-ce une étape importante ?

    1. Découplage : Le "Front-end" (le script) est totalement séparé du "Back-end" (Django).
    2. Multi-plateforme : On pourrait remplacer ce script Python par du JavaScript (pour un site web) ou du Swift (pour une application iPhone), l'API Django resterait la même.
    3. Automatisation : On peut imaginer un script qui poste automatiquement un article chaque matin.

    Mini-TP

    Modifier le script pour envoyer un nouvel article en utilisant requests.post().

    Indice : Il faudra envoyer un dictionnaire data = {"titre": "...", "contenu": "..."} et utiliser requests.post(URL, data=data).
